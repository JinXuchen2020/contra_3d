# 战斗系统设计（shooter_contra 模板）

## 定位
魂斗罗风格 run-and-gun 3D 射击的战斗核心。本文档只描述职责划分、依赖与数据流，不涉及具体实现。

## 子系统职责划分
- weapon_system（武器系统）
  - 管理武器定义：伤害、射速、弹速、弹道类型（直线/抛物线/散射）、弹匣与换弹时间
  - 处理武器切换（主/副武器槽）与射击请求的合法性校验（冷却、弹药）
- projectile_system（弹体系统）
  - 生成、推进、回收弹体；管理弹道与生命周期（超时、出界销毁）
  - 附带发射者阵营信息，用于命中判定时的敌我识别
- health_damage（生命与伤害系统）
  - 唯一有权修改实体生命值的模块
  - 伤害计算：基础伤害 × 距离衰减 × 部位倍率，处理护甲减免
  - 死亡处理：广播死亡事件、掉落与积分结算、销毁/回收实体
- hit_detection（命中判定，隶属 projectile_system）
  - 弹体与受击体的相交检测；使用容差补偿高速弹体的穿透问题

## 系统间依赖
```
input_system → weapon_system → projectile_system → hit_detection → health_damage
                     ↑                                  │
                     └──────（弹药/冷却状态回读）────────┘
```
- weapon_system 不直接扣血，只产出"射击事件"
- projectile_system 不读武器配置之外的游戏状态
- health_damage 是伤害写入的唯一入口，禁止其他系统直改生命值
- 死亡通过事件通知 respawn/刷兵/积分等下游系统，战斗系统不感知下游

## 数据流（单次射击）
1. 输入层捕获开火/切换指令 → weapon_system
2. weapon_system 校验冷却与弹药 → 产出射击事件（起点、方向、武器参数）
3. projectile_system 生成弹体，按弹道类型逐帧推进
4. hit_detection 检测弹体与目标相交（带容差）
5. 命中事件携带伤害参数 → health_damage 结算
6. 生命归零 → 死亡事件广播

## 关键数值约束
- 标准敌人 TTK：0.5–3.0 秒（按武器与敌人等级浮动），禁止一击必杀普通杂兵（Boss 除外）
- 命中判定容差：弹体按速度单帧位移的 1.0–1.5 倍做扫掠扩径，避免高速穿模
- 射速下限：同一武器两次射击间隔 ≥ 0.08s，防止输入连点导致的事件风暴
- 同屏弹体上限：≤ 200，超出时优先回收最旧弹体
- 伤害计算必须确定性：同输入同状态产出同结果，便于回放与联机同步

## 验收标准清单
- [ ] 玩家可在 ≥ 3 种武器间无缝切换，切换动画/冷却期间无法射击
- [ ] 直线/散射/抛物线三种弹道均表现正确，弹体超时与出界正常回收
- [ ] 高速弹体（≥ 30 m/s）不发生可见穿透（容差扫掠生效）
- [ ] 伤害只经 health_damage 修改生命值，代码审查无旁路写入
- [ ] 标准武器击杀标准杂兵的实际 TTK 落在 0.5–3.0s 区间
- [ ] 同屏 200 弹体压力测试下帧率不低于目标帧率的 90%
- [ ] 死亡事件触发后掉落、积分、刷兵计数均正确联动
