# 敌人 AI 系统设计（shooter_contra 模板）

## 定位
定义魂斗罗风格 run-and-gun 3D 射击的敌人行为。只描述状态机与规则，不涉及实现。

## ai_type 定义（4 种）
| ai_type | 行为概述 | 典型武器 |
|---|---|---|
| patrol | 沿路径巡逻，遇警触发后短暂警告再交战 | 近战/手枪 |
| chase | 发现玩家后持续追击并近身压制 | 冲锋枪/近战 |
| sniper | 占点远距离狙杀，被逼近则后撤换位 | 狙击枪 |
| rusher | 无视掩护直冲玩家，接触即自爆/扑击 | 自爆/爪击 |

## 状态机定义
通用状态集合与转换条件（每种 ai_type 启用子集并调参）：

- **patrol**：`Patrol → Alert（视距内发现玩家，警觉值≥阈值）→ Combat → Patrol（玩家死亡或脱离追击范围且警觉值归零）`
- **chase**：`Idle/Alert → Chase（发现玩家）→ Attack（进入攻击距离）→ Chase（脱离攻击距离）`
- **sniper**：`Hold → Aim（视距内且瞄准线清晰）→ Fire（瞄准时间到）→ Reposition（玩家接近至安全距离内）→ Aim`
- **rusher**：`Spawn → Rush（感知到玩家方向）→ Explode/Strike（接触判定半径内）→ Death`
- 公共转换：任意状态 `→ Dead`（health_damage 死亡事件）；`→ Staggered`（受击硬直，短暂后回原状态）
- 状态机每帧输出：移动意图、朝向、开火请求——交给移动/战斗系统执行，AI 不直接写战斗数值

## 感知系统
- 视距：patrol 15m / chase 20m / sniper 35m / rusher 12m
- 视角：patrol/sniper 有朝向扇形（90°–120°），chase/rusher 接近全向
- 警觉值（0–100）：
  - 玩家在视野内：+20/s；玩家开火声（40m 内）：+35；被命中：直接拉满
  - 无刺激时衰减 10/s；≥ 60 进入 Alert，= 100 确认目标进入 Combat
- 简化遮挡检测：视线被障碍阻断时不累计视觉警觉值（听觉不受限）

## 刷兵系统
- spawn point：地图上预置刷兵点，携带 ai_type 权重、触发方式（进区域触发/定时/事件）
- 同屏上限：普通敌人 ≤ 12，rusher ≤ 4；超限时刷兵请求排队
- 死亡回收：敌人死亡后由 combat_system 死亡事件驱动计数递减，释放刷兵配额
- 防堵门规则：玩家 5m 半径内不刷兵；连续阵亡 3 次的点位临时降低权重

## Boss 多阶段模式框架
- Boss 由阶段（Phase）+ 招式（Move）两层组成：
  - Phase 按血量百分比切换（如 100–70% / 70–35% / 35–0%），切换时清空当前招式并播放转阶段表现
  - 每个 Phase 配置招式池与权重，招式=一段带前后摇的行为脚本 + 弱点窗口
- 阶段切换只允许单向推进，血量回升不回退阶段
- 转阶段无敌期 1.5–2.5s，期间免疫伤害与硬直
- Boss 复用上述感知与状态机接口，仅状态集合扩展为 Phase 内招式节点

## 验收标准清单
- [ ] 4 种 ai_type 在测试关中行为符合上表概述，状态转换无死锁
- [ ] 警觉值增减与归零符合规则，敌人不会无Trigger永久交战
- [ ] 同屏敌人数不超过上限，超限时刷兵排队且不丢失
- [ ] 玩家近身刷兵点不会原地刷出敌人（防堵门生效）
- [ ] Boss 三个阶段单向切换、转阶段无敌表现正确，血量回升不回退
- [ ] 敌人 AI 帧开销：同屏 12 敌人时占用低于单帧预算的 10%
- [ ] 敌人死亡事件正确联动刷兵配额与积分
